# iVOLT — Registro de decisiones (ADR)

Formato: contexto → decisión → consecuencias → rechazado. Estado A = aceptada, R = rechazada. Fecha 2026-09-13 salvo indicación.

## ADR-001 Monorepo con npm workspaces y un solo paquete publicable (A)
Tres entregables (paquete, docs, starters) deben probarse juntos. npm workspaces con un lockfile bastan. Rechazado: pnpm/Turborepo/Nx (infraestructura sin necesidad demostrada); varios paquetes `@ivolt/*` (fragmenta versiones antes de tener usuarios).

## ADR-002 Cadena de build: esbuild + lightningcss + scripts Node (A)
Un empaquetador por lenguaje, ambos rápidos y con minificado, targets y sourcemaps. lightningcss resuelve `@import`, anidamiento y `@custom-media`. Rechazado: Sass (segunda sintaxis y compilador para lo que CSS nativo ya hace), PostCSS con plugins (más dependencias por lo mismo), Rollup/Vite modo librería (duplican esbuild), compilador de utilidades propio (fuera de v0.1).

## ADR-003 Tokens en un JSON propio con generador de 100–200 líneas (A)
Esquema pequeño: `$type`, `$value`, alias `{a.b}`; emite CSS (temas), custom-media, JSON resuelto y breakpoints JS. Rechazado: Style Dictionary (potente, pero su configuración y transformaciones superan la necesidad; se reconsidera si aparecen más plataformas).

## ADR-004 Módulos CSS sin capa; las entradas asignan `@layer` (A)
Permite `ivolt.css` con capas, `ivolt.flat.css` sin ellas y la importación por componente, desde el mismo código. Consecuencia documentada: `@layer` no aísla frente a CSS externo sin capa; se ofrece la entrada plana y la receta de envolver CSS legado en una capa. Rechazado: solo capas (pierde contra `button {}` de temas WordPress); solo sin capas (pierde la sobrescritura sencilla).

## ADR-005 Gramática BEM acotada + utilidades `iv-u-` con infijo de breakpoint (A)
`iv-bloque__elemento--modificador`, `iv-u-<bp>-<prop>-<valor>`. Los estados JS se reflejan en atributos nativos/ARIA, no en clases `is-*`. Rechazado: clases de estado (`.is-open`) porque duplican lo que ya expresa `open`/`aria-expanded` y desincronizan CSS y semántica.

## ADR-006 Tema por `data-iv-theme` con valor `system` y light por defecto (A)
Funciona sin JS ni storage; la elección explícita anidada prevalece. `theme.js` opcional con persistencia opt-in. Rechazado: clase `.dark` en `html` (sin ámbito anidado ni valor system); dark por defecto (impone la estética de marca al consumidor).

## ADR-007 Ciclo de vida explícito: `init`/`destroy`, WeakMap, sin observador global, sin efectos de importación (A)
Predecible, tree-shakable y compatible con SSR/CSP. `auto.js` es la única entrada con efecto. Rechazado: autoarranque en `index.js`; `MutationObserver` global por defecto (coste continuo y sorpresas en CMS); registro por import (rompe `sideEffects`).

## ADR-008 `<dialog>` nativo con `showModal()` sin polyfill (A)
La matriz de navegadores (Safari ≥ 16.4) lo soporta; el navegador aporta top layer, `inert` implícito y Esc. iVOLT añade retorno de foco, foco inicial, eventos y cierre por backdrop. Drawer reutiliza `<dialog>` en móvil. Rechazado: diálogo con `div` + trap de foco manual (más JS, más errores); polyfill (peso y matriz que no pedimos).

## ADR-009 Matriz de navegadores: Chrome/Edge 111, Firefox 113, Safari 16.4, Samsung 22 (A)
Determinada por `color-mix()`, `@layer`, container queries, `:has()`, `<dialog>`, `inert`. Rechazado: soportar Safari 15 (sin `dialog` fiable ni `inert`); IE.

## ADR-010 JS en ES modules con JSDoc; tipos emitidos por `tsc`; sin TypeScript fuente (A)
El consumidor recibe JS legible igual al fuente; el tipado se comprueba en CI. Riesgo: TypeScript 7.x (nuevo compilador) puede no emitir declaraciones desde JS igual que 5.x; fase 1 fijó 5.9.3 directamente (emisión verificada) y deja 7.x para cuando aporte algo. Rechazado: TS fuente (paso de compilación para todo el paquete).

## ADR-011 Web de docs con Astro estático, sin framework de UI, búsqueda con Pagefind (A)
HTML y CSS del propio paquete; JS mínimo por página. Pagefind indexa la salida estática y se sirve local (sin peticiones externas). Rechazado: Starlight (impone su diseño y componentes), React/Vue (innecesarios), búsqueda remota.

## ADR-012 Utilidades: matriz finita generada; sin JIT, purga ni valores arbitrarios (A)
Integraciones CMS usan clases documentadas sin escáner. Rechazado: reproducir Tailwind.

## ADR-013 Fuentes: paquete con `system-ui`; docs pueden añadir una geométrica libre local en fase 3 (A)
Cero peticiones y licencia registrada cuando se incorpore. Rechazado: fuente remota obligatoria; tipografía display para textos largos.

## ADR-014 Web Components / Shadow DOM como formato de entrega (R)
Rompen el consumo CSS puro, el theming global por tokens y la sencillez en WordPress/PHP; pueden evaluarse como capa opcional futura.

## ADR-015 Sin `!important` salvo `.iv-u-sr-only` (A)
La composición se apoya en capas y variables locales. Excepción única documentada y probada por contrato.

## ADR-016 Política de modelos: Fable lidera y revisa; Opus 5 implementa; sin delegación recursiva (A)
Ver WORKFLOW. Rechazado: Fable en todas las tareas (coste), agentes subordinados Fable.

## ADR-017 Logo pendiente: wordmark temporal propio (A, resuelto 2026-09-13)
Mientras no existía el logo se usó un SVG provisional. Resuelto: los archivos oficiales viven en `assets/brand/` y `apps/docs/src/brand.js` los transforma para cada uso (tema, favicon, OG) sin modificar el original; el wordmark temporal permanece solo como fallback para que un checkout sin assets construya.

## ADR-018 Pruebas: Vitest + Playwright + axe-core; sin Jest ni Cypress (A)
Un runner unitario y uno de navegador con tres motores. Rechazado: Storybook en v0.1 (las fixtures de docs cumplen ese papel).

## ADR-019 Utilidades con especificidad (0,2,0) por selector doblado; componentes ≤ (0,2,0) (A)
Sin capas (`ivolt.flat.css`) el orden utilidades > componentes no existía. Doblar el selector (`.iv-u-x.iv-u-x`) e importar utilidades al final lo garantiza en ambas entradas con el mismo módulo. Coste: unos cientos de bytes gzip. Rechazado: `!important` en utilidades (rompe el principio de composición y el contrato de `!important`); generar dos módulos de utilidades distintos.

## ADR-020 Mejora progresiva: `init` promueve el HTML servido a widget ARIA (A)
Tabs y dropdown se sirven como enlaces de ancla y `<details>` sin roles de widget, funcionales sin JS y correctos para lectores de pantalla; `init` añade roles, `aria-*`, roving tabindex y `hidden`, y `destroy` los retira. Rechazado: servir `role="tablist"`/`role="menu"` en el HTML (anuncian un patrón que sin JS no funciona ni es alcanzable por teclado).

## ADR-021 Drawer: un único `<dialog>` que el CSS muestra estático desde `lg` (A)
Un `<dialog>` cerrado se muestra con `display:block` en ≥ lg sin `open` (contenido accesible, fuera del top layer); en < lg se abre con `showModal()`. Un `matchMedia` cierra el modal al cruzar hacia arriba. Rechazado: dos elementos (`<dialog>` y `<aside>`) con el mismo contenido duplicado.

## ADR-022 Cierre de `<dialog>` siempre interceptado para mantener `iv:close` cancelable (A)
`submit` de `form[method=dialog]`, `cancel` (Esc) y clic en backdrop se interceptan antes del cierre nativo. Los cierres externos directos emiten solo `iv:closed` con `reason: "external"`. Los enlaces con `data-iv-open` hacen `preventDefault()` con JS; no hay enlace profundo a diálogos en v0.1.

## ADR-023 Excepción única de especificidad: `.iv-dialog:target:not([open])` y `.iv-drawer:target:not([open])` (0,3,0) (A)
El fallback sin JS del diálogo necesita `:target` y excluir el estado abierto con JS; acotarlo con `:root:not([data-iv-js])` costaría (0,4,0). Se registra como única excepción al techo (0,2,0) y el test de contrato la lista explícitamente. Con JS, el delegador cancela la navegación del ancla, así que `:target` nunca se activa.

## ADR-024 `box-sizing: border-box` acotado a `.iv-root` en `base.css` (A)
El reset es opcional; sin `border-box`, `iv-container` e `iv-input` (width 100% + padding) desbordan. `base.css` lo aplica a `.iv-root` y descendientes (especificidad ≤ (0,1,0) + universal). Detectado por la prueba de overflow a 320–1920 px en fase 1.

## ADR-025 Un ámbito `[data-iv-theme]` reaplica `color` y `background-color` (A)
Los tokens cambian por ámbito, pero `color` heredado ya está calculado en el padre: una sección `dark` dentro de una página `light` mostraba texto claro solo en los elementos que declaraban color. `tokens.css` emite `[data-iv-theme] { color: var(--iv-color-text); background-color: var(--iv-color-bg); }` en la capa `iv.tokens`; componentes y utilidades lo sobrescriben. Detectado por axe (contraste 1.14:1) en la fixture de temas anidados.

## ADR-026 `danger-hover`/`danger-active` derivados con `color-mix()` en vez de tokens nuevos (A)
`button.css` deriva los estados del botón `--danger` con `color-mix(in oklab, …)` sobre `--iv-color-danger` y `--iv-color-text`, correcto en ambos temas y dentro de la matriz de navegadores. Se reconsidera como token si otra familia lo necesita.

## ADR-027 Listón de diseño de la web: nivel de premio (A, 2026-09-14)
Decisión del propietario del producto: la web de iVOLT debe tener un diseño lo bastante bueno como para optar con posibilidades reales a un reconocimiento en Awwwards, CSS Design Awards o galerías equivalentes (Site of the Day, nominación o destacado). Esto sustituye la dirección de fase 0 «aire, líneas finas, un solo detalle memorable» por una dirección rica en movimiento y efectos, sin renunciar a los límites técnicos del contrato: sin vídeo de fondo, sin partículas pesadas, sin WebGL obligatorio, sin cursor personalizado, sin ruido tras el texto; experiencia completa con `prefers-reduced-motion`; presupuestos de rendimiento y accesibilidad intactos (Lighthouse, axe, teclado). Criterios operativos en `DESIGN_SYSTEM.md` §8. Lo que no se puede prometer: un premio depende de un jurado; lo que sí se exige es cumplir esos criterios de forma verificable. Rechazado: delegar el rediseño a un agente (se ejecuta directamente por el líder por decisión del propietario).

## ADR-028 Sin rejillas de fondo; rediseño ronda 2 por implementador Opus; hito beta (A, 2026-09-14)
Tras revisar el rediseño ADR-027 el propietario lo califica de «muy muy deficiente» y prohíbe las rejillas de fondo: ninguna cuadrícula ni patrón de puntos en fondos, hero, tarjetas o previsualizaciones salvo petición explícita en el encargo. Se retiran las existentes (campo del hero y previsualizaciones de fixtures). Sustituye la última frase de ADR-027: la segunda ronda del rediseño vuelve al flujo normal (implementador Opus con encargo acotado en `docs/design/DIRECTION_R2.md`, revisión y capturas del líder, aceptación del propietario). El propietario fija además el objetivo inmediato: no detener el roadmap hasta tener una beta; el hito se define en `ROADMAP.md` §5.

## ADR-029 Arquitectura de la web tras la ronda 2: hojas por ámbito, `bleed`, cabecera de página derivada, i18n por prefijo (A, 2026-09-14)
`docs.css` pasa a ser un índice de cuatro hojas (`base.css`, `shell.css`, `home.css`, `motion.css`; la última concentra `prefers-reduced-motion`, único lugar con `!important` en la web). `Base.astro` acepta `bleed` (la home sale del contenedor) y `lang`; el idioma se resuelve por la prop o por el prefijo `/es` de la ruta, y de él dependen cadenas (`i18n/en.js`, `i18n/es.js`, mismas claves), navegación, `<html lang>`, `hreflang` (`en`, `es`, `x-default`) y el selector de idioma, que navega con recarga completa (`data-astro-reload`) para que Pagefind cargue el índice del idioma correcto. La cabecera de página (eyebrow con grupo y familia `css`/`js`) se deriva del `nav` y del mapa `families` exportado por `en.js`, única fuente también para la lista de la home. Las páginas en español son archivos propios bajo `src/pages/es/` (contenido redactado por idioma, no traducción en tiempo de ejecución). Rechazado: `astro:i18n` con enrutado automático (añade configuración y redirecciones que no aportan nada a un sitio estático de dos idiomas).

## ADR-030 El framework también debe ser espectacular: capa expresiva v0.3 y presupuestos nuevos (A, 2026-09-14)
Revisión del propietario tras la beta: «sigue todo siendo muy genérico (me refiero al framework) y nada espectacular». Pide, como ejemplos, un slideshow espectacular, formularios mucho más trabajados (select tipo Select2, contador de caracteres/palabras, comprobación de errores), glassmorphism y texturas. Nada de eso estaba en el roadmap: la fase 0 fijó una dirección sobria («aire, líneas finas, un detalle memorable») y el backlog solo tenía el carrusel en P2. Decisión: la dirección de arte del framework pasa a ser expresiva por defecto (ADR-027 se extiende del sitio al producto) sin tocar el contrato técnico: HTML servido funcional sin JS, `init`/`destroy` exactos, sin dependencias, sin `!important`, especificidad ≤ (0,2,0), tokens como API, `prefers-reduced-motion` con experiencia completa, accesibilidad probada. Se abre el ciclo v0.3 («Spectacular», `ROADMAP.md` §6) con contratos §8.5–§8.8: carrusel cinematográfico, selector enriquecido (`picker`), validación de formularios y contador, enriquecimiento CSS de formularios, y un módulo de superficies (cristal, grano, mallas de gradiente, aurora, bordes luminosos) con tokens `glass`, `blur`, `glow`, `texture`. Presupuestos: el JS agrupado pasa de 18 a 32 KiB gzip y `ivolt.min.css` de 30 a 40 KiB (regla de QUALITY §1: el umbral cambia con ADR, nunca en silencio); el coste real por módulo se registra al cierre del ciclo. Rechazado: dependencias externas para el carrusel o el selector (rompen el principio de cero dependencias y el theming por tokens); efectos que solo funcionen con JS (el CSS servido debe dar ya un resultado digno).

## ADR-031 Picker: chips fuera del botón, modificador `--active`, `search` como cadena (A, 2026-09-14)
Hallazgos del implementador del selector enriquecido: (a) §8.6 colocaba los chips con su botón de borrado dentro del `<button>` de control, HTML inválido (interactivo dentro de interactivo) y de anuncio dudoso; (b) el resalte `.is-active` rompía la regla «toda clase empieza por `iv-`»; (c) `search: "auto"|boolean` es una unión que la gramática de opciones (§5.2, un tipo por opción) no admite y provocaba un aviso falso. Decisiones: los chips viven en `ul.iv-picker__chips` dentro de `div.iv-picker__field`, hermano del `button.iv-picker__control`; el resalte es `iv-picker__option--active`; `search` toma `auto|on|off`. La gramática de opciones no aprende uniones: una opción con más de dos estados usa cadenas. Rechazado: contenedor `role="combobox"` con chips y búsqueda dentro (patrón Select2): más ARIA que explicar y sin ventaja sobre un botón real más una lista de chips.

## ADR-032 Todo `select.iv-select` se enriquece por defecto; colocación del popover por espacio real (A, 2026-09-14)
Revisión del propietario tras v0.3: «no veo select2 en todos los selects; los que lo tienen a veces el dropdown sale arriba y se corta cuando hay espacio suficiente abajo». Decisiones: (a) `Picker.initAll` envuelve cualquier `select.iv-select` sin raíz en un `div.iv-picker` generado (`data-iv-auto`, retirado en `destroy`), con `data-iv-native` como salida explícita: la mejora pasa a ser opt-out, coherente con ADR-030; (b) el popover prefiere abajo, solo sube cuando no cabe abajo y hay más sitio arriba, y `--iv-picker-max-height` se fija al espacio disponible para que la lista nunca se corte; (c) las previsualizaciones de la web dejan de recortar (`overflow: visible` en `.docs-fixture`) y pierden la traslación al pasar el puntero, que convertía a la fixture en bloque contenedor de las regiones `position: fixed` (los toasts saltaban de sitio al hacer hover). Rechazado: mover la lista a un `popover` de la capa superior (rompe el contrato de restauración exacta y el posicionamiento relativo sin JS).

## ADR-033 v0.4/v0.5 tras la revisión del propietario: aprender de sus webs sin heredar dependencias (A, 2026-09-14)
El propietario pide megamenús, bordes con destello y proximidad y heros espectaculares tomando como referencia brokenufo.com y clasicosbasicos.org (temas suyos), y no parar hasta 0.5. Se estudian sus hojas y scripts (`bufo-core.css`, `mega-menu.js`, `reveal-fx.js`, `navigation.css`, `cinematic.css`, `portada.css`) y se adoptan los patrones (panel absoluto centrado, superposición, `inert`, acordeón móvil, `scan`, `spark`, halos, revelados por intersección), no el código ni las dependencias (GSAP/ScrollTrigger quedan fuera por el contrato de cero dependencias). Contratos §8.9–§8.11; el ciclo v0.4 empieza por una revisión adversaria con dos revisores Opus, porque el propietario reporta «muchos errores» y tres ya se confirmaron (ADR-032).

## ADR-034 Hallazgos de la revisión adversaria fuera de contrato: toasts en la capa superior, combobox colocado por espacio, `inert` en todas las diapositivas (A, 2026-09-14)
El revisor de componentes demostró tres límites del contrato: un toast crítico queda oculto e inaccesible bajo un `<dialog>` modal (la capa superior gana a `position: fixed`); la lista del combobox no se voltea ni se acota al viewport (el picker sí, §8.6); las diapositivas fuera de pantalla del carrusel en `slide` siguen en el orden de tabulación. Decisiones: la región de toasts entra en la capa superior con `popover="manual"` cuando existe soporte, con el `position: fixed` actual como respaldo (verificado: se pinta sobre el modal; la interacción sigue bloqueada por el modal, que mantiene inerte el resto, y se acepta); el combobox adopta la colocación medida del picker con `--iv-combobox-max-height` y `data-iv-placement`; el carrusel aplica `inert`/`aria-hidden` a las no visibles en todos los efectos. Aceptado también: el estado de un acordeón exclusivo tras la interacción es del usuario y `destroy` no lo revierte; la fixture del drawer oculta sus controles donde el panel es estático (ejemplos honestos).

## ADR-035 Hallazgos de la revisión adversaria de la web y del CSS: cabecera desde 80 em, anclas bajo la cabecera, colores forzados, palabras sin corte (A, 2026-09-14)
El revisor demostró 46 combinaciones ruta/ancho con desbordamiento horizontal y controles invisibles en `forced-colors`. Decisiones: la barra de navegación de escritorio de la web se activa desde 80 em (la cabecera española necesita ~1214 px y a 64 em solo hay 942), con lo que entre 1024 y 1279 px conviven el botón de menú y la barra lateral (aceptado); los destinos de ancla llevan `scroll-margin-block-start` bajo la cabecera pegajosa; el código en línea y los `h1` admiten corte (`overflow-wrap: anywhere`); `iv-switch` e `iv-range` declaran bordes y relleno con colores de sistema bajo `forced-colors: active` (precedente en `tabs.css`; regla general: todo control con estado dibujado por color lleva un bloque `forced-colors`); botones, migas y alertas cortan palabras sin espacios. Mantenido a propósito: `.iv-badge` con `white-space: nowrap` (insignias de una línea en celdas; una palabra de 45 caracteres es un dato mal formado, no un caso de diseño).

## ADR-036 Datepicker: `aria-selected` en la celda, `Today` selecciona, envoltorio de control (A, 2026-09-14)
El implementador demostró con axe que `aria-selected` en el `<button>` del día es una violación crítica (`aria-allowed-attr`): el atributo va en la celda `gridcell` y el CSS pinta `[aria-selected="true"] > .iv-datepicker__day`. Se aceptan además: `Today` selecciona hoy y cierra (simétrico con `Clear`, deshabilitado fuera de rango); un `div.iv-datepicker__control` generado envuelve input, toggle y popover porque la raíz es el campo entero; cabeceras con `weekday: "short"`; el teclado se detiene en `min`/`max`; `step` en días respetado; colocación arriba solo si cabe arriba. Pendiente señalado por el implementador: `.iv-dialog__title` pierde contra `.iv-root h2` en la hoja plana (revisar aparte).

## ADR-037 Presupuesto de JS agrupado a 48 KiB gzip (A, 2026-09-14)
Con tooltip y popover, `index.js` agrupado (21 componentes) pasa de 32 KiB. El presupuesto sube a 48 KiB con la tabla por módulo en `QUALITY.md` §1; el argumento sigue siendo el de ADR-030: cada módulo se importa por separado (`exports`, tree-shaking verificado por `pack-smoke`), así que el agrupado mide la suma, no el coste de un consumidor. El presupuesto de CSS (40 KiB) no cambia (20,3 KiB medidos). Rechazado: excluir componentes del `init` por defecto para maquillar la cifra.

## ADR-038 Composición entre componentes: `Command` reutiliza `Dialog` (A, 2026-09-14)
§5.2 decía «ningún componente importa a otro» para evitar acoplamientos y duplicar la lógica modal era peor: la paleta de comandos es un diálogo. Se autoriza la composición explícita cuando un componente *es* otro más comportamiento: importa solo la API pública (`getOrCreate`, `open`, `close`, `isOpen`, `destroy`), crea la instancia solo si no existe y la destruye solo si la creó. Se mantiene la prohibición de dependencias circulares y de tocar el DOM del otro componente. Aceptado del implementador: `iv:commanded` también en ítems con `href`; activar cierra siempre (una opción `closeOnSelect` queda para cuando haya demanda); `__status` en inglés hasta que se defina `statusText`.

## ADR-039 Segunda revisión del propietario sobre la web: mirar antes de afirmar, fotos libres, columna ancha (A, 2026-09-14)
Tras `0.5.0-beta.0` el propietario reporta: efectos de borde que «no funcionan», megamenú que «se va antes de poder entrar», contenido descentrado o apretado, un filete bajo los títulos que no entiende, columna central estrecha; pide ver la web «de verdad» con Playwright, mejorarla brutalmente, mejorar el framework y usar imágenes libres para carruseles y heros. Decisiones: (a) toda afirmación visual pasa por capturas reales en Chromium (y tres motores al cerrar), en ambos idiomas y temas; (b) fotografías de Unsplash vía Lorem Picsum, acreditadas en `apps/docs/public/photos/README.md` y `THIRD_PARTY.md`, solo como activos de la web: las fixtures con fotos viven en `apps/docs/fixtures/` y las sirven `Fixture.astro` (fallback) y `scripts/serve.mjs` (fallback y alias `/photos/`); el paquete npm sigue sin mapas de bits; (c) la columna de prosa pasa de la medida tipográfica (~65ch) a 72rem con párrafos a 72ch, y desaparece el filete bajo el `h1`; (d) el megamenú ignora el hover de ítems sin panel, tapa el hueco bajo la barra con un `::before` mientras está abierto y cierra a los 320 ms; (e) `iv-edge-near` e `iv-edge-glint` suman un halo (`box-shadow`) al anillo enmascarado, porque un anillo de 1–3 px no se percibe como «efecto». Dos revisores Opus con Playwright rematan la web y el pulido visual del framework, y el líder integra.

## ADR-040 Rediseño de la web y pulido visual del framework; carrera de prueba en el cierre del diálogo (A, 2026-09-14)
Dos implementadores Opus con Playwright, integrados por el líder. Web: una sola escala vertical (`--docs-flow/block/sub/section`) con secciones numeradas y filete, columna de lectura que llenan fixtures, tablas y bloques de código (≥ 820 px a 1440), heros con fotografía en las páginas de inicio, mapa del sitio en el pie en ambos idiomas, bloques `docs-meta` y `docs-note`, tablas anchas en su propia región de scroll enfocable, 404 con destinos reales y `qa-docs-overhaul.spec.js`, que mide la maqueta a 390, 1024 y 1440. ## ADR-041 Ciclo v0.6 «Structure»: tokens con nombre, cabecera de sitio, asistente por pasos, toast declarativo y bloques de contenido (A, 2026-09-14)
Petición del propietario: «sigue trabajando hasta 0.7». Alcance de 0.6 (`ROADMAP.md` §9, contratos §8.15–§8.19 escritos antes de implementar): (a) los seis tokens que el pulido visual dejó como recetas repetidas (`--iv-shadow-ambient`, `--iv-color-hover-surface`, `--iv-color-primary-border`, `--iv-focus-halo`, `--iv-tracking-tight`, `--iv-tracking-caps`) pasan a `tokens.json` y once módulos los consumen; las filas al hover conservan `primary-subtle` porque cambiarlas alteraría el aspecto; el local `--iv-progress-height` se renombra a `--iv-progress-size` (cambio anotado en el changelog de una beta sin publicar); toda tarjeta se eleva al hover bajo `(hover: hover)`; (b) `Navbar` pliega por un atributo de estado `data-iv-collapsible` escrito por JS y no por `@media`, para que `collapseBelow` sea real y nada se pliegue sin JS; refleja `data-iv-sticky` y escribe `scroll-padding-block-start` mientras es pegajoso; `hideOnScroll` conserva su traslación bajo reduced motion porque es estado; un megamenú alojado se compone con `position: static` en su lista y sin superposición; (c) `Stepper` valida con `Form.validateField` cuando hay instancia y con `reportValidity` si no; en modo lineal el alcance es «hasta el paso más lejano visitado»; los controles se sirven ocultos y `init` los muestra; (d) `Toast` acepta disparadores `data-iv-toast` con un solo listener delegado por región y expone `showFromTrigger`; (e) `iv-timeline`, `iv-stat` e `iv-avatar` son CSS puro; el solape del grupo de avatares se resuelve en cada avatar (`calc(var(--iv-avatar-size) * -0.18)`) porque un `calc()` declarado en el grupo no resolvía la variable; el tono del delta de una cifra expresa sentimiento y el signo vive en el texto. Método: dos implementadores Opus con archivos disjuntos y capturas propias, un tercero para la web; el líder añadió la fixture y la prueba de `hideOnScroll`, registró las enmiendas en el contrato y regeneró las líneas base a propósito. Versión `0.6.0-beta.0`, sin publicar.

## ADR-042 Ciclo v0.7 «Media & motion»: visor de imágenes, movimiento por scroll, texto y contador; la barra de lectura es estado (A, 2026-09-14)
Alcance (`ROADMAP.md` §10, contratos §8.20–§8.23 escritos antes de implementar): `Lightbox` sobre `Dialog`, `motion.css` con `ScrollMotion` como reserva para navegadores sin `animation-timeline` (hoy Firefox; Chromium y WebKit lo tienen), `text.css` con `Countup`, y la receta «showcase» con seis fotografías propias acreditadas. Decisiones al integrar: (a) la barra de progreso de lectura sigue la página también bajo `prefers-reduced-motion: reduce`, porque es estado (posición de lectura) y no desplazamiento, con el mismo criterio que `hideOnScroll` en ADR-041; `ScrollMotion` escribe `--iv-scroll` bajo reduced motion y omite `--iv-view` (los parallax quedan estáticos); (b) `iv-parallax-frame` recorta con `overflow: clip` porque `hidden` crea un contenedor de scroll y congela `view()`; (c) `iv-stack-cards` con `animation-range: exit` hace retroceder toda la baraja al salir, no un relevo por tarjeta: se acepta para 0.7 y el relevo por tarjeta queda como candidato; (d) `iv-text-outline` e `iv-text-shimmer` usan `-webkit-text-fill-color` y el color primario (el acento bajaba el contraste en claro), y los efectos de texto se recomiendan a tamaños display; (e) el visor es una sala oscura en ambos temas (chips con locales anclados a la paleta) y el clic en el entorno cierra con `reason: "backdrop"`; con zoom el escenario es una región de scroll enfocable y las flechas desplazan la imagen; (f) sin JS un `href` `data:` no navega, así que las fixtures del paquete lo dicen y la web demuestra la galería con fotografías reales; (g) `Countup` restituye los nodos servidos y `decimals: -1` es «auto». Lecciones nuevas para el contrato de trabajo: `:where()` a especificidad cero no puede envolver un estado entero (el estado pierde contra la regla base y solo la captura lo ve); la captura de puntero reetiqueta el `click`. Recetas: `build-downloads` solo empaqueta carpetas con `index.html`, para que los activos preparados antes de una receta no salgan solos en un zip. Hallazgo de Lighthouse en la receta showcase (móvil, rendimiento 69, CLS 0,38): el panel del navbar se sirve abierto y `init` lo pliega después del primer pintado, desplazando toda la página; decisión: el CSS pliega desde el primer pintado por debajo de `lg` cuando la raíz llega marcada con `data-iv-js` por un script en línea en `<head>` (misma técnica que el tema sin destello de la web), `init` escribe siempre un valor en `data-iv-collapsible` (`""` o `"false"`) para distinguir el estado previo, y el riesgo (script que no llega: panel plegado sin toggle) queda documentado; sin la marca todo sigue como antes. Versión `0.7.0-beta.0`, sin publicar.

## ADR-043 Primera publicación en npm: `0.7.0-beta.0` con etiqueta `beta` (A, 2026-09-14)
El propietario intentó instalar `@intervolutions/ivolt@0.5.0-beta.0` (404: nada estaba publicado) y autorizó por escrito la publicación («confirmo, haz lo que debas, permiso total»). Ejecutado desde este entorno con su cuenta (`davabe`): el `npm login` interactivo dejó la sesión pero la cuenta exige 2FA para publicar (`EOTP`), así que se usó un token de acceso granular facilitado por el propietario, cargado en un `userconfig` temporal con permisos 600 y borrado tras el comando; el propietario lo rota. Publicado `0.7.0-beta.0` con `--access public --tag beta`; npm asigna además `latest` a la primera versión de un paquete (no existe un paquete sin `latest`), lo que se documenta en lugar de fingir lo contrario; `latest` pasará a la primera estable. Cambios derivados: la página de inicio, los README y el changelog anuncian `npm install @intervolutions/ivolt@beta`; `check-examples` deja de vetar «npm install» y sigue vetando CDN; etiqueta git `v0.7.0-beta.0` en origin; `npm pkg fix` normalizó `repository.url`. La web sigue sin desplegar: eso requiere una autorización aparte.

## ADR-044 Presupuesto de JavaScript hasta 1.0: techo de 48 KiB para el agrupado y coste por módulo publicado (A, 2026-09-15)
Al cerrar v0.7 el agrupado de los 24 componentes quedó en 42,8 KiB gzip, a 5 KiB del techo de 48 (ADR-037). Decisión: el techo se mantiene hasta 1.0 y no es un objetivo sino un guardarraíl; v0.8 y v0.9 no añaden familias JS, solo correcciones. `npm run sizes` mide desde ahora cada componente agrupado por separado con la parte del núcleo que arrastra (lo que paga quien importa `@intervolutions/ivolt/<módulo>`): entre 1,9 KiB (`reveal`) y 6,6 KiB (`command`), y cada hoja de `dist/css` por separado (0,4–3,5 KiB). Con esas cifras la recomendación pública para 1.0 es: hoja completa (28 KiB) más importación por módulo cuando una página usa hasta seis componentes; el agrupado o el IIFE cuando usa más. Si un ciclo posterior a 1.0 superase los 48 KiB, se abre un ADR con las cifras por módulo, nunca se sube el umbral en silencio (regla de `QUALITY.md` §1).
