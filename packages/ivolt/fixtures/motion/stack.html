Sample copy for the fixture. Each card sticks one step lower than the one before it, so the deck reads as a deck. Where the engine has scroll-driven animations each card shrinks and dims exactly while the next one rides over it (the deck serves --iv-stack-count and every card its --iv-i); where it does not, the stack is still a stack and nothing is lost. The text of the cards describes this project.

01

Contracts first

Every family of this framework is written as a contract before a line of it is implemented: markup, classes, options, events, accessibility and what is out of scope.

02

One grammar

Classes start with iv-, custom properties with --iv-, attributes with data-iv- and events with iv:. Nothing else is allowed in.

03

HTML that already works

The served markup is complete. JavaScript upgrades it; it never creates the thing the page is for.

04

Motion with an argument

Movement is transform and opacity, it has a reason, and prefers-reduced-motion removes all of it while leaving the composition whole.

After the deck

Filler, so the last card can leave the top of the window and the whole deck can be scrolled past: the shrink of a card only runs while it is on its way out.

Under prefers-reduced-motion: reduce the cards keep their sticky offsets and drop the scale and the fade.
